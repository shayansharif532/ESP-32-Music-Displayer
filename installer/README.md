# DeskMedia Companion - Windows installer

How the Windows installer is built, tested, signed and used unattended. For end users the story is in
[../docs/installation.md](../docs/installation.md); this page is for whoever builds or ships the installer.

| | |
|---|---|
| Result | `installer\output\DeskMediaCompanion-Setup-<version>.exe` (about 18 MB) and a `.sha256` file; the version comes from `desk_media_companion.__version__` |
| Installs | the packaged companion (`DeskMediaCompanion.exe` + its runtime) **per user**, to `%LOCALAPPDATA%\Programs\DeskMedia Companion` |
| Needs | Windows 10 version 1809 (build 17763) or Windows 11, 64-bit (the media-session API of Windows 10 1809 is the floor) |
| Does not | ask for administrator rights, need a reboot, touch the Windows Firewall, or change any Windows security setting |
| Tool | [Inno Setup 6](https://jrsoftware.org/isinfo.php) (6.3 or newer; developed with 6.7.3) |

## Build

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build_release.ps1
```

That is the whole pipeline. It creates / reuses `companion\.venv` (64-bit Python 3.12), installs `requirements.txt` +
`requirements-build.txt` (PyInstaller), generates the version files from `desk_media_companion.__version__`, runs PyInstaller on
[`companion/DeskMediaCompanion.spec`](../companion/DeskMediaCompanion.spec), checks the result (windowless x64 exe, manifest,
version resource, icon, bundled assets, then `--version` / `--selftest` of the packaged exe in a scrubbed environment) and compiles
`DeskMediaCompanion.iss`. A normal build takes about 80 seconds. `companion\build.ps1` is a thin entry that stops after the app folder.

| Switch | Effect |
|---|---|
| `-SkipInstaller` | only the app folder `companion\dist\DeskMediaCompanion\` and its checks |
| `-SkipSelfTest` | do not run the packaged exe |
| `-RunTests` | run the unit tests first |
| `-Clean` | delete `companion\build` and `companion\dist` first |
| `-Python <exe>` | interpreter used to create the venv when it does not exist |
| `-ProjectUrl <url>` | home page shown in Programs and Features (default: none; `origin` = the GitHub URL of the origin remote - it contains the owner's account name) |
| `-SignTool "<command>"` | optional code signing, see [below](#code-signing-optional) |

Where things go (all git-ignored): `companion\dist`, `companion\build`, `companion\version_info.txt`, `installer\version.iss`,
`installer\build`, `installer\output`. The artwork (`installer\assets\*`: icon and wizard images) is generated by `make_assets.py` with
Pillow - synthetic shapes, no text, no third-party art - and **committed**, so a build never needs to regenerate it.

| File | Role |
|---|---|
| `companion/DeskMediaCompanion.spec` | the single source of truth of the app build (hidden imports, data files, icon, manifest, version resource) |
| `companion/DeskMediaCompanion.manifest` | `asInvoker` (never a UAC prompt), Windows 10 / 11, DPI awareness, common controls 6 |
| `companion/run_companion.py` | the exe's entry shim: `--version`, `--selftest`, `--quit`, the quit listener, crash log |
| `companion/desk_media_companion/selftest.py` | what `--selftest` runs |
| `tools/release_meta.py` | writes `companion/version_info.txt` and `installer/version.iss` from `__version__` (the only place a version is edited) |
| `installer/DeskMediaCompanion.iss` | the Inno Setup script |
| `installer/make_assets.py`, `installer/make_notices.py` | icon + wizard images; third-party notices as the text page Setup shows |

### Why a folder (onedir) and not one file

A PyInstaller one-file exe unpacks about 25 MB of Python, Tcl/Tk and DLLs into `%TEMP%` on **every** start: slow (the tray icon appears
late), and "a program that extracts and runs code from a temp folder" is exactly what antivirus heuristics flag. The installer puts the
folder in place once and every start loads it directly. UPX is off for the same reason. A side effect that matters for the LGPL
(pystray): the library files are separate files in `_internal\`, so a user can replace them.

### Reproducibility

`SOURCE_DATE_EPOCH` is the last commit's time (PE timestamps), `PYTHONHASHSEED` is fixed, the version resource's year is the last commit's year,
Inno Setup stores UTC timestamps. The same commit and the same package versions give the same app folder; the installer is not byte-identical
run to run (Inno's compressor embeds its own build data). Pin the package versions in `requirements.txt` if you need more.

## Test

Three scripts, all Python standard library (they need the venv's Python only for PyInstaller where noted). None of them touches the
real `HKCU\...\Run` value `DeskMediaCompanion`, the real `%LOCALAPPDATA%\DeskMediaCompanion`, a running companion, the firewall or a serial port.

```powershell
# 1. Clean-machine-style test of the REAL installer: install silently into a throw-away folder, run the installed exe with a
#    scrubbed environment, look for traces of this PC, uninstall, prove nothing real was touched. Starts nothing that listens.
companion\.venv\Scripts\python.exe tools\installer_smoke_test.py installer\output\DeskMediaCompanion-Setup-1.0.0.exe

# 2. Lifecycle test of the installer SCRIPT in a sandbox variant (other AppId / Run value / data folder, a stand-in app):
#    install, upgrade, auto-start handling, running-copy gate, shortcuts, uninstall keep / delete data.
companion\.venv\Scripts\python.exe tools\installer_flow_test.py

# 3. Does a running packaged companion obey `--quit` (what the installer uses for upgrades and uninstalling)? Starts the real exe with
#    --no-usb (no serial port is touched), --no-tray, a private data folder and quit event; first with NO network port at all (the
#    default of the USB-first product), then with --lan on 127.0.0.1:8799 (never 8765).
companion\.venv\Scripts\python.exe tools\quit_listener_test.py
```

The smoke test installs with the real AppId, so it refuses to run on a PC where the product is already installed. It scans every installed
file (raw bytes as ASCII and UTF-16, zip members, and the compiled modules inside the exe's PyInstaller archive) for the Windows user name,
`C:\Users\<you>`, the profile folder, the repository and checkout paths, `.venv` and the computer name; `unins000.dat` is skipped because Setup
writes the installing PC's own user and computer name there by design. A positive control proves the scan finds planted strings.
Run it on a second, clean PC or VM with `--no-skip-mutex` to test the real "a companion is running" gate; add `--needle` strings for any
other name that must not appear.

`DeskMediaCompanion.exe --selftest` can also be run by hand on any PC: it prints one JSON line and exits 0 / 1 (details in
`desk_media_companion/selftest.py`). Windowless, the exe has no stdout, so the line is also written to `%TEMP%\deskmedia-selftest.json`,
and `--version` writes `%TEMP%\deskmedia-version.txt` (no message box: a dialog would block unattended runs).

## What the installer does

* **Pages:** Welcome - the third-party notices (information only: the project has no licence file yet, so there is no "I accept" page) -
  Options - install - Finish. No folder page (it installs to `%LOCALAPPDATA%\Programs\DeskMedia Companion`; `/DIR` overrides).
* **Options:** *Start DeskMedia Companion when I sign in to Windows* (ticked) and *Create a desktop shortcut* (unticked). A Start menu
  shortcut is always created. The auto-start option writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `DeskMediaCompanion` =
  `"<install folder>\DeskMediaCompanion.exe" --quiet`, the very value the tray menu's *Start with Windows* writes, so the two agree.
* **Finish:** *Start DeskMedia Companion now* (ticked) and two sentences: plug the display into a USB port, confirm the pairing code the first time.
  When silent, the companion is started as well (unattended installs end with a running companion; `/NOLAUNCH` prevents it).
* **Upgrade in place:** run a newer installer over the old one. A running companion is asked to quit first (`DeskMediaCompanion.exe --quit`),
  then Windows' Restart Manager closes anything still using the files; the runtime folder is replaced completely (no stale files). Settings,
  pairing and the log live outside the install folder and are never touched. *Start with Windows* is offered as it is now: if the user switched
  it off in the tray menu, an upgrade does not switch it back on.
* **Uninstall** (Settings > Apps, or `unins000.exe`): quits the companion, removes the files, the shortcuts and the auto-start entry (also one
  switched on from the tray menu later, but only if it points at this installation). It asks whether to also delete the settings and the pairing
  in `%LOCALAPPDATA%\DeskMediaCompanion`; **the default is No (keep)**. Silent uninstall keeps them unless `/DELETEDATA` is passed.
* **Running-copy check:** Setup refuses to continue while another copy of the companion is running: the companion's single-instance
  lock is the mutex `Local\DeskMediaCompanion` (taken by every instance that may use USB; it does not depend on any HTTP port - the
  product has none unless the optional LAN mode is on, and a LAN-only development instance takes only `Local\DeskMediaCompanion-lan-<port>`,
  which does not block an install). A copy of *this* installation is quit automatically first, so in practice the check only stops an
  install when some other copy (for example a developer's) is running. The quit request is a named kernel event
  (`Local\DeskMediaCompanion-Quit`), not HTTP; `quit_listener_test.py` proves it works with no network port.
* **Network and firewall:** the installer never touches the Windows Firewall or any other system setting, and in USB mode (the default) the
  companion opens no listening socket, so Windows has no reason to show a firewall question. Only the optional LAN mode (`--lan` or the
  `lan_enabled` setting) opens a TCP port and a UDP beacon, and Windows may then ask.

### Silent install and uninstall

```powershell
DeskMediaCompanion-Setup-1.0.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CURRENTUSER /DIR="D:\Apps\DeskMedia Companion" /TASKS="autostart,!desktopicon" /LOG="%TEMP%\dm-setup.log"
"%LOCALAPPDATA%\Programs\DeskMedia Companion\unins000.exe" /VERYSILENT /SUPPRESSMSGBOXES /NORESTART [/DELETEDATA]
```

| Switch | Meaning |
|---|---|
| `/VERYSILENT` (`/SILENT`) | no wizard (no progress window) |
| `/SUPPRESSMSGBOXES` | answer every question with its default (needed for truly unattended runs) |
| `/NORESTART` | never restart (the installer never needs to) |
| `/CURRENTUSER` | accepted; the installer is per-user anyway |
| `/DIR="path"` | install folder (default `%LOCALAPPDATA%\Programs\DeskMedia Companion`) |
| `/TASKS="a,b"` / `/MERGETASKS="!a"` | tasks: `autostart` (start when I sign in), `desktopicon`. `/TASKS` replaces the defaults (`/TASKS=""` = none), `/MERGETASKS` changes them. Without either, an upgrade keeps the current auto-start state |
| `/NOICONS` | no Start menu shortcut |
| `/NOLAUNCH` | do not start the companion after installing (also when silent) |
| `/SKIPMUTEXCHECK` | do not refuse while another copy runs - for automated tests on a developer PC |
| `/LOG="file"` | write a Setup log (without a file name: a unique file in `%TEMP%`) |
| uninstaller `/DELETEDATA` | also delete `%LOCALAPPDATA%\DeskMediaCompanion` (settings, pairing, log); never implied |

Exit codes of Setup (Inno Setup's): `0` success, `1` failed to initialise (e.g. another copy is running), `2` cancelled before install,
`3`/`4` fatal error, `5` cancelled during install, `7`/`8` the "preparing" step cannot continue.

### Where things live

| What | Where |
|---|---|
| Program | `%LOCALAPPDATA%\Programs\DeskMedia Companion\` (`DeskMediaCompanion.exe`, `_internal\`, `LICENSES\`, `THIRD_PARTY_NOTICES.txt`, `unins000.*`) |
| Settings, idle-screen picture, pairing (DPAPI-protected), log | `%LOCALAPPDATA%\DeskMediaCompanion\` - **kept** by upgrades and, by default, by uninstalling |
| Auto-start | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `DeskMediaCompanion` |
| Uninstall entry | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{73454063-9F9F-4C5A-9818-1D7B6B45C5F7}_is1` (the AppId; never change it, it ties upgrades together) |
| Shortcuts | Start menu: *DeskMedia Companion*; desktop (optional) |

## SmartScreen and code signing

**What users will see.** The installer is not signed. When it was downloaded with a browser (or came as an e-mail attachment) Windows
marks it as coming from the internet, and Microsoft Defender SmartScreen may show a blue window, *"Windows protected your PC - Microsoft
Defender SmartScreen prevented an unrecognized app from starting"*, with *Publisher: Unknown publisher*. The way through is:
**More info** (a link in that window) -> **Run anyway**. Nothing is wrong with the file; the warning is about the missing signature and
the missing "reputation". A file copied from a USB stick or a network share is usually not marked and shows no such screen. Setup itself never needs an
administrator prompt (the manifest says `asInvoker`), so there is no UAC dialog after that. Some antivirus programs are also wary of any
PyInstaller program; the one-folder layout and no UPX keep that to a minimum, and a false positive can be reported to the vendor.

**What signing would change.** With a code-signing certificate the publisher name appears instead of "Unknown publisher", the signature
proves the file was not altered after signing, and SmartScreen reputation builds up for the certificate instead of starting from zero for each
new file. It does not make the warning disappear on the first day of a new certificate, and certificates cost money (an organisation-validated
certificate, a signing service, or free signing programmes for open-source projects, where the project qualifies; check current terms).

**The hook (optional, nothing needs it).** Pass the command Inno Setup should run for each file; `$f` stands for the file:

```powershell
.\tools\build_release.ps1 -SignTool 'signtool.exe sign /fd sha256 /td sha256 /tr http://timestamp.example.org /f C:\keys\code.pfx /p secret $f'
```

This defines the `signtool` command for Inno Setup (`/Ssigntool=...`) and turns on `SignTool=signtool` + `SignedUninstaller=yes` in the script;
the installer, the uninstaller and `DeskMediaCompanion.exe` are signed. Quote carefully (Inno Setup uses `$q` for a double quote inside the
command, `$p` for a percent sign) and keep the certificate and its password out of the repository.

## The recipient's first run (what the installer is for)

Run Setup (three clicks on Next, a few seconds) -> the companion starts and sits next to the clock -> plug the display into a USB port ->
the display tells how far it has got (*USB - Companion - Paired*): if it shows **Install DeskMedia Companion** the companion is not
running on that PC (install it, or start it from the Start menu); if it shows **Pair with your PC**, compare the six-digit codes and confirm
once on both ends -> done. Every later day: plug in, nothing to do (the companion starts with Windows). The wording for non-developers is in
[../docs/installation.md](../docs/installation.md).

## Decisions that belong to the project owner

| Decision | State now |
|---|---|
| Code signing certificate | none: unsigned build, SmartScreen "Unknown publisher" (above). Signing is optional and supported by the build |
| Where the installer is downloaded from | the display's *Install DeskMedia Companion* screen (QR code + address) points at `DM_SETUP_URL` in `firmware/main/app_config.h` (default: the GitHub releases page). That page must offer `DeskMediaCompanion-Setup-<version>.exe` and be reachable by the recipient, or the firmware must be built with another `-DDM_SETUP_URL` |
| Project URL in *Programs and Features* | none by default (`-ProjectUrl`): a GitHub URL contains the owner's account name |
| Publisher text | `DeskMedia Display project` (installer, uninstall entry, exe version resource) - change in `tools/release_meta.py` and `installer/DeskMediaCompanion.iss` |
| Project licence | none yet, so Setup shows the third-party notices as information instead of a licence page; when a `LICENSE` file exists, switch `InfoBeforeFile` to `LicenseFile` |
| Third-party notices | `THIRD_PARTY_NOTICES.md` section 3 must list everything inside the exe: **pyserial** (BSD-3-Clause) is bundled now but only appears in the development-tools section |

## Troubleshooting

| Symptom | What to check |
|---|---|
| Setup says it "has detected that DeskMedia Companion is currently running" | Quit the companion (tray icon > *Quit*), or it is another copy (a development one); then click OK |
| Setup exits with code 1 silently | a copy is running (add `/LOG`, read the log); or the PC is older than Windows 10 1809 / 32-bit |
| The tray icon does not appear after installing | run `DeskMediaCompanion.exe --selftest` (see above); read `%LOCALAPPDATA%\DeskMediaCompanion\companion.log` (a crash is logged there) |
| `ISCC.exe` not found by the build | install Inno Setup 6 or set `$env:ISCC` |
| The build fails at the self-test | the JSON line names the failed check; a missing hidden import shows up as `package_modules` / the named dependency |
