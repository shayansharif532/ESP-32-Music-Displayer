# ADR-008 — The idle screen is a synthetic item of the vertical source ring (2026-10-12) — **current**

Status: **accepted** (maintainer request after using M9). Builds on ADR-005 / ADR-006 (the ring and AUTO / MANUAL_TEMP) and ADR-007 (the idle screen). Details and evidence: [`docs/development-history/M9b-idle-source.md`](../development-history/M9b-idle-source.md).

* **One more item in the same ring.** The vertical swipe now walks `usable sessions (alphabetical) ... Idle Screen`, the idle item always **last**, wrapping at both ends: `Spotify <-> Chrome <-> Idle Screen`. It has its own identity, `idle` (`sources.IDLE_ID`), and is **not faked as a Windows session**: it is
  never read through WinRT, never has a title / state / volume, and is offered whenever the companion is connected (with no session at all the ring is just `[idle]`, so a swipe does nothing; with one session plus Idle it is two sources). `/now-playing`'s `sources` / `source_index` count it; `GET /sources` lists it as a row with `"synthetic": true`.
* **Selecting Idle is a display choice, never a playback command.** It is a `MANUAL_TEMP` selection like any other (`Selector.select`), so media keeps playing in the background, no control is sent to any app, and the companion keeps the connection (the display just stops showing a session). While it is selected `/now-playing` carries `idle_selected: true`
  and `mode: "manual"`; its other fields still describe what AUTO would show, so the player underneath is current when the user swipes back.
* **Auto-follow is preserved; Idle never pins.** It ends when **any session starts playing** (a pause -> play transition, or a new playing session appearing) - the display then follows that session, exactly like leaving any manual selection - and by `POST /control/source-auto` or a tap on the idle screen.
  Two deliberate differences from a session selection: it cannot "disappear", and **the 20 s return does not apply** - Idle is typically chosen *while something plays* ("Spotify keeps playing in the background"), and the user may stay on it as long as nothing new starts.
* **Controls while Idle is shown (selected or shown automatically): nothing reaches media.** The transport controls live on the player screen, so they are simply not there; horizontal swipes are consumed and do nothing; the **side volume keys do nothing** (the display ignores them; the companion also refuses every `/control/*` and volume request with `app=idle`
  - "the idle screen is selected: nothing to control" - so no path can change an unrelated app's volume). Documented choice: not "control the last real session", to avoid accidental changes.
* **The display names what it shows.** Source requests carry `from=idle` when the idle screen is up - whether the user selected it or the display went there by itself because nothing plays (ADR-007) - so a swipe is always relative to what the user sees: up from Idle -> the first session, down from Idle -> the last. A swipe from the automatic idle screen onto a paused session shows its player and keeps it up
  (a swipe counts as using it, the 30 s hold of ADR-007), so it does not bounce back to idle.
* **Idle selected overrides the delay logic** (`idle_wanted`): shown at once and whatever plays. A tap on a *selected* idle screen leaves the choice (`POST /control/source-auto`, then the player); a tap on the automatic idle screen keeps its ADR-007 meaning (peek at a paused session). A short guard ignores a stale selection report for 1.5 s after such a tap.
* **Feedback.** The same source pill as for apps, subtle: "Idle Screen" + position dots (4 dots with two sessions). The pill follows the screen that is becoming visible (re-parented to the idle screen), because it lives on one screen at a time. The idle screen understands the vertical swipe with the player's thresholds and safeguards (`ui_attach_vertical_swipes`); a sloppy diagonal is not a tap (`ui_touch_moved`).
* **Rejected:** moving the auto-idle decision (delay, peek) into the companion (it works, is tested, and needs the display's own timers); a "pin" semantic for Idle (violates auto-follow); letting the volume keys fall through to the last real session (an accidental change of an app the user cannot see).
